# Answers of the forum's app API, as test data

`forum_v2_*.json` (forum page, `schema: 2`), `thread_v3_*.json` (thread page, `schema: 3`) and `profile_v4_*.json`
(profile page, `schema: 4`: the account's own page, two other members, a lookup by username, the guest and the unknown
user messages) are real answers of the `tsdmapp` plugin, fetched from a test forum and scrubbed. They are regenerated by
a tool kept with the plugin, not by hand: the tool fetches every case again, drops `document`/`head`, rewrites the test
forum's host and name (and, on the profile page, the viewer's own IP rows), and normalizes the fields that change on
every request so the tests can pin them:

- `formhash` → `f1f2f3f4`
- `reply.posttime` → `1700000000`
- `thread.views` → `100`

`forum_v2_fid2.json`, `thread_v3_plain.json` and `profile_v4_self.json` carry a deliberate garbage `document`: the tests
prove the structured path never reads it. `forum_v2_fid29_pending.json` is hand-written (the pending-application
message). The `profile_v4_*.json` answers (plugin 2.2.0, 2026-10-20) were scrubbed with the same rules by a script, until
the tool covers the profile page. Everything else must not be edited by hand; change the plugin or the tool instead.
